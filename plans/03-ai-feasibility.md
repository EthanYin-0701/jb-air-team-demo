# AI 能力分工与可行性验证

## 最重要的能力边界

用户需要的是宠物主体图片与参考舞蹈共同驱动的视频生成。一个仅支持图片加文本的视频模型，即使能生成“跳舞的猫”，也不能据此认定支持参考舞蹈迁移。

本设计以 OpenRouter Models 为两个下拉菜单的唯一目录来源：提示词整理使用 output_modalities=text 与 arch=Gemini，视频生成使用 output_modalities=video，并从 /api/v1/videos/models 补充能力。默认采用已确认存在的 OpenRouter 原生视频生成、查询和下载接口；目录可见但调用链路未实测的模型展示为不可选，不假定目录分类等于已经接通。

当前要求：**基础提示词必须由用户下拉选择的 Gemini 再加工，视频生成模型也由用户下拉选择，并只接收通过校验的再加工结果。** 此要求替代此前固定 Gemini 3.7 Flash 的约束；不再以该具体名称是否存在作为前置条件，也不硬编码一个 Gemini 版本。

已通过官方 GitHub SDK 固定版本确认接口定义，详见 [08-openrouter-api-verification.md](./08-openrouter-api-verification.md)。实时目录、账户权限、模型路由及实际效果仍未实测；以下质量方案仍是待执行实验，不是已有结果。

## 两条生成路径

| 路径 | 输入与作用 | 可以向用户承诺什么 |
| --- | --- | --- |
| A：参考动作迁移，优先验证 | 主体图片 + 真实参考视频进入生成模型；大模型辅助描述外观和动作 | 达到质量门槛后，称为“参考舞蹈生成”，仍不承诺逐帧复制 |
| B：舞蹈灵感生成，受限备选 | 从参考片段得到动作描述，以图片 + 动作文字驱动视频模型 | 仅能称“舞蹈灵感生成”，动作节奏和姿态不保证对应 |

路径 B 不是 A 的隐式容灾。若 A 不可用，必须在提交和费用确认之前明确切换能力说明，并由用户重新确认；不能先收费再静默改成 B。

如果没有可接受的 A 路径且产品仍坚持动作迁移，停止该核心功能上线，保留设计和实验报告，不能用随机舞蹈或预置视频冒充。

## OpenRouter 工作流

1. 服务端按具体模型能力准备宠物图像。提取物种、主要毛色、耳形、脸部与身体识别特征，以及是否明显多主体、过暗或遮挡。
   宠物素材支持本地或 URL 图片/视频；视频由用户选择代表帧作为身份图，可在模型支持且有必要时附加少量分析帧。宠物视频与舞蹈视频的角色分别保存；原始宠物视频不因上传成功就被宣称可直接驱动视频模型。
2. 判断选定模型是否真正支持视频输入，核实媒体容器、时长、大小、传输格式和可访问性。
3. 支持视频时，提交已经裁剪的参考片段；不支持时，使用受限数量的抽帧辅助理解动作，并在内部标注时间信息缺失。初始实验可采用约 1 fps、最多 8 帧，实际以成本及模型输入限制调整。
4. 输出结构化的动作概括：动作类型、节奏快慢、移动方向、镜头变化、遮挡问题、适配宠物时需要保留或弱化的动作。
5. 先由版本化模板形成基础提示词，包含宠物身份、舞蹈概括、风格、画幅及保留主体等约束，再通过 OpenRouter 调用用户所选 Gemini 再加工成适配所选视频模型的提示词。基础模板、两个所选模型、再加工调用、最终提示词摘要及版本关联同一任务；参考素材中的文字和模型输出都视为数据，不能改写系统策略。
6. 校验返回格式、长度及枚举，不合格时最多做一次受控修复；仍失败则停止并提供可重试原因。

只有再加工成功且内容通过校验，才进入视频生成提交。Gemini 不可用、模型不存在或输出不合格时，不直接提交基础提示词，也不悄悄替换模型。所有该任务的 OpenRouter 调用及修复均需采集实际 token 与费用，详见追加需求。

抽帧分析不能恢复完整速度、节奏或连续运动。A 路径仍须将原始裁剪片段交给视频生成服务；文字概括只能辅助，不能替代参考视频。

大模型质量判断不作为安全保证。确定性文件检查、用户权限和费用控制全部由服务端执行。宠物质量提示默认可由用户覆盖，无法解码、超限或安全违规则不可覆盖。

## 视频生成适配层

适配层统一承担：能力发现、预估成本、提交任务、查询状态、可选取消、校验回调、取回产物和规范化错误。

| 能力属性 | 实施前必须核验 |
| --- | --- |
| 输入组合 | 是否能同时提供宠物图片和动作参考视频，而非只支持首帧、文本或换背景 |
| 动作控制 | 是否真实使用参考动作；是否限定人体、姿态骨架或人脸 |
| 主体范围 | 猫狗、四足到直立的动作表现，复杂毛发和尾巴是否稳定 |
| 规格 | 时长档位、画幅、分辨率、帧率、容器、输入上限及输出水印 |
| 异步行为 | 提交回执、幂等支持、状态查询、回调真实性、取消及超时规则 |
| 可靠性 | 冷启动、队列长度、限流、失败率、服务区域、产物链接有效期 |
| 成本 | 每次/每秒计费、失败和取消计费、重试费用、流量和存储成本 |
| 数据与许可 | 上传权限、商业使用、素材保留、训练使用、删除支持及部署区域 |

候选模型仅来自 OpenRouter Models 的 Video 输出分类，匹配专用视频目录后通过原生 /api/v1/videos 执行，不用独立供应商目录填充菜单。官方 input_references 支持视频类型，但不支持的提供方可能忽略视频参考；必须逐模型及端点验证真实动作关联，并避免路由到忽略参考的提供方。模型名字包含“animate”“motion”不等于适合宠物，不能将单纯的人物替换或人类姿态迁移当作已解决动物舞蹈生成。

## 最小验证实验

先进行小批次筛选，再扩大验证，避免在不合适的模型上浪费完整产品开发成本。

### 第一轮：排除能力不符

- 为每个候选服务选择 2 张自有宠物照、2 段自有或获授权的舞蹈片段，共 4 个组合；先不做付费实验以外的基础设施。
- 验证接口能否真实接受输入组合；记录请求规格、供应商任务号、费用及实际等待时间。
- 对“同宠物、不同舞蹈”做对照，观察动作是否随参考变化；对“同舞蹈、不同宠物”观察身份是否保留。
- 任一关键输入不支持、动物表现普遍失真或数据条款不满足要求，直接淘汰。

### 第二轮：质量与稳定性

- 建议准备 6 张宠物照（猫狗各 3 张，覆盖毛色、全身和半身）及 4 个动作片段（缓慢摆动、左右踏步、转身、较快手臂动作），共 24 个组合。
- 每组合先生成一次；从边缘案例中选至少 6 个额外重复，检验随机性。单个候选至少 30 个样本，费用上限在真实报价后确定。
- 由至少 2 名评价者独立看原图、参考片段和产物；分歧记录并复核，不用模型自评代替人工观察。
- 若半身或快速动作不能稳定通过，可明确收缩为全身照片与低复杂度舞蹈，并同步修改前台范围。

### 评分与建议通过门槛

| 维度 | 1–5 分定义中的 5 分目标 |
| --- | --- |
| 身份保持 | 面部、毛色和主要特征稳定，用户能认出原宠物 |
| 动作关联 | 主要移动方向、动作顺序与节奏可辨地对应参考 |
| 身体稳定 | 无严重多肢、融合、突然换脸或身体断裂 |
| 时间连续性 | 无明显闪烁、瞬移和大段静帧 |
| 可播放性 | 文件可解码、时长与规格符合提交摘要 |

建议首版门槛：至少 80% 样本的身份保持 ≥4、动作关联 ≥3、身体稳定 ≥3；全体样本严重身体崩坏率 ≤10%，可播放性 100%。这是规划门槛，不是已有测试结果。

通过质量门槛后，还需满足真实预算和可接受等待时间；按成功任务计算平均成本，并记录 p50 / p95 耗时和失败费用，防止仅计算理想成功一次的价格。

## 容灾与模型变更

- 提示词再加工和视频生成都固定执行用户所选模型 ID，不自动跨型号替换；同型号提供方路由须满足数据策略且记录来源。素材分析若使用额外模型，需在报价、费用明细和数据说明中披露，不能暗中增加一次付费模型选择。
- 视频服务不自动跨供应商重试付费请求。超时或失去响应时优先查询已有任务，无法确认结果则进入“待确认”，避免重复付费。
- 不把提交的未知结果判为失败后马上再提交；没有幂等或按客户引用查找能力的供应商，需要人工对账或禁用自动重提。
- 固定模型标识和供应商配置版本，关键变更重新跑代表性样本，不直接跟随无版本的 latest 行为。
- 数据不外传到未披露供应商；无合规等价备选时显式报暂不可用。
