# PawGroove · 宠物跳舞 Web App 设计方案

状态：设计提案，尚未进入开发。整理日期：2026-10-15。

## 产品概念

使用 Next.js 构建一个中文优先的 Web App：用户通过本地上传或 HTTPS 媒体 URL 提供宠物图片、宠物视频及参考舞蹈视频，选取片段后生成一段宠物跳舞短视频。暂定品牌名 **PawGroove / 爪爪舞台**，可在开发前调整。

核心体验是「宠物素材 + 一段参考舞蹈 → 一段可预览、下载的宠物跳舞视频」。提交给视频模型的基础提示词必须先经 OpenRouter 上用户指定的 **Gemini 3.7 Flash** 再加工；准确模型名称及 API ID 待核验，不自动替换为其他模型。最终视频通过另行验证的视频生成服务完成。结果页显示任务关联的 OpenRouter token 消耗及实际 credit 消耗明细。

## 已知事实与规划假设

- 当前仓库没有应用代码、依赖或现有设计体系。本次仅新增 plans 中的设计文档。
- 用户明确指定 Next.js、OpenRouter、Gemini 3.7 Flash 提示词再加工、本地及 URL 图片/视频、任务 token 和 credit 明细；未指定视频生成供应商、部署平台、预算、登录或收费方式。
- 默认按个人创作工具设计：一个主体、一份宠物图片或视频、一个短舞蹈片段、一次生成一个结果。宠物视频可由用户选择代表帧，首版优先猫和狗。
- “跟着参考视频跳舞”与“生成一段有舞蹈感觉的视频”是不同能力。正式产品必须按实测结果表述，不能将后者包装成前者。
- 网络视频默认指用户有权使用的可下载媒体直链；公开视频平台分享页不等于可直接导入的媒体地址。
- 不假定 OpenRouter 当前可直接生成视频，也不预设任何指定模型支持完整视频输入或动物动作迁移。

## 调研边界

本次尝试使用联网检索和直接访问官方文档，但当前环境分别返回工具错误和网络代理 403，未能核实实时资料。因此下列链接仅作为实施前核验入口；本方案不引用其未读取的内容，不承诺当前模型可用性、接口参数、价格、配额或许可范围。

- [OpenRouter 文档](https://openrouter.ai/docs)：确认图像输入、视频输入、模型目录、结构化输出、超时及数据策略。
- [fal 官方站点](https://fal.ai/)：候选视频服务调研入口，重点寻找同时接收主体图片与动作参考视频的能力。
- [Replicate 文档](https://replicate.com/docs)：候选异步模型托管服务调研入口，核验具体模型输入及许可。
- [Next.js 官方文档](https://nextjs.org/docs)：实施时锁定稳定版本，并核验部署环境对运行时和请求时长的限制。

## 开发前的关键决策

先用少量真实猫狗照片和舞蹈片段验证动作迁移。若没有供应商达到效果、成本及数据要求，则收缩为“舞蹈灵感生成”并明确说明，或暂停核心功能实现，不能仅用页面演示证明可行。

建议的默认方向：趣味、轻拟人化、短片优先；保留宠物面部、毛色和识别特征，允许合理直立，但不承诺逐帧复现人体舞姿。
